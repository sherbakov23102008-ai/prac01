1. Гипотеза
Я думаю, что второй раз программа собирается быстрее, потому что часть файлов уже готова.

2. Результаты
- Первый запуск - 2,40 с.
- Второй запуск - 0,75 с.
- После изменения кода — 1,10 с.
Наблюдение: Первая сборка заняла больше всего времени - 2,40 с. Вторая прошла быстрее - 0,75 с. После изменения одной строки время увеличилось до 1,10 с, но сборка всё равно была быстрее первой.
3. Папки bin и obj
В bin находятся готовые файлы программы, а в obj - временные файлы, которые нужны для сборки. Файлы .cache помогают системе понять, что изменилось.
4. Удаление папок
Если удалить только bin, готовые файлы создадутся заново. Если удалить ещё и obj, сборка обычно займёт больше времени.
5. Файл .csproj
В нём указаны настройки проекта и версия .NET.
6. Вывод
Я выяснил, что повторная сборка обычно проходит быстрее, если код не менялся. Это происходит потому, что компьютер может использовать файлы от прошлой сборки.
Контрольные вопросы:
1. Потому что часть файлов уже готова.
2. В bin готовые файлы, а в obj временные.
3. Сборка будет занимать больше времени.
4. Чтобы указать настройки проекта.
5. Потому что не все файлы нужно собирать заново.
6. Потому что эти папки можно создать повторно, и хранить их в Git необязательно.
